## Outstanding assumptions

- Python 3.10 or later is available locally.
- Generation time is not a concern: medium took 2.7 s on the maintainer's Mac (one measurement, not a benchmark).
- The distributions (path weights, rates, price ranges, regional weights) are illustrative.
- Lakeflow Auto Loader reads header-only CSVs and LF line endings without special options. To verify in Phase 03.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Code has never been run | Phase blocked until fixed | Runbook Steps 3-4 surface errors first, on the tiny preset |
| Generator and validator share a misunderstanding | Both agree on wrong data | Independent test of paid totals; Phase 03 compares silver with `_expected/` |
| Medium preset too slow | Slower iteration | Use small for development; record timings |
| Contract changes not propagated | Generator constants drift from the contract | `generate()` refuses to run if methods or categories differ from the contract |

## Phase 02 prerequisites

1. Phase 01 runbook completed with every validation passing, and committed.
2. Java installed for local PySpark (`java -version`; Java 17 suggested in `docs/platform_assumptions.md`), plus the PySpark version to pin. Phase 02 will propose one; it depends on your Python version.
3. Decision on legacy input semantics. Proposed default for Phase 02:
   - the legacy job reads `batch_000` plus every change batch in folder order
   - for each key, the row from the last file read wins ("last file wins")
   - no deduplication of payments

   That reproduces realistic legacy errors on late arrivals and replays, which Phase 06 then explains.
4. Explicit approval to start Phase 02.
